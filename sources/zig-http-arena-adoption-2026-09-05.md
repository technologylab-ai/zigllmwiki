# Current bounded implementation

Each connection has one64KiB output arena; heads are generated at `begin()`
from an owner cache, generated bytes follow, small borrows up to256bytes are
copied/counted when they fit, and larger spans remain borrowed until terminal
completion. No kernel/NIC zero-copy is implemented. Batches default128 and
accept1–511; callbacks default to connections × batch limit capped8192 per
shard per turn. Both are finite startup limits. Receive/send/cancel records
number4C+2 per shard. Each shard may transiently accept an overflow descriptor;
shared admitted connections remain bounded by C. Each Linux shard reserves full
slot capacity; defaults auto-select at most16 allowed CPUs. Mac supports one.
Workers require one shard; multiple inline shards invoke shared application
state concurrently, which requires immutability or application synchronization.

Review fixes snapshot the Date/header cache into worker-owned slot storage,
hold prearmed body parsing behind interim SEND, preserve responses after peer
write-half EOF, sample at exactly16callbacks, gate all shard request I/O behind
startup preparation, unwind partial startup, propagate secondary-owner failure,
and include coordinator/arrays/stacks in exact requested-byte accounting.
Exit acknowledgements precede joins under a finite watchdog; unreconciled
owners terminate the process. A violating primary inline callback still needs
an external watchdog; arbitrary app preemption or isolation is not promised.
